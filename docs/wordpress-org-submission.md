# WordPress.org submission checklist — Webba Deploy

Use this before submitting at [wordpress.org/plugins/developers/add/](https://wordpress.org/plugins/developers/add/).

## Removed / excluded from release zip (audit 1.0.0)

| Item | Reason |
|------|--------|
| `includes/Security/Crypto.php` | Unused duplicate of `SecretEncryption` |
| `includes/GitHub/WebhookManager.php` | Empty Phase 5 placeholder |
| `includes/Rest/GitHubWebhookController.php` | Empty Phase 5 placeholder |
| `PLAN.md`, `docs/development.md`, `docs/wordpress-org-submission.md` | Internal / dev-only (`.distignore`) |
| `build/`, `vendor/`, `scripts/`, `composer.json` | Dev tooling (`.distignore` + `.gitignore`) |
| `assets/wordpress-org/` | SVN `assets/` only, not plugin zip |

Legacy GitHub callback URLs (`admin.php?page=…&action=…`) remain supported for existing App registrations.

## Version sync (every release)

- [ ] `webba-deploy.php` — `Version:` header matches release
- [ ] `webba-deploy.php` — `WEBBA_DEPLOY_VERSION` constant matches release
- [ ] `readme.txt` — `Stable tag:` matches release
- [ ] `readme.txt` — new `== Changelog ==` section for the release
- [ ] `readme.txt` — `Tested up to:` reflects latest WordPress you tested against
- [ ] Git tag created (e.g. `v1.0.0`)

## readme.txt

- [ ] **Contributors** uses your [wordpress.org username](https://profiles.wordpress.org/) slug (currently `giodc` — change if your profile slug differs)
- [ ] Short description (line after the blank line) is under ~150 characters
- [ ] **External services** and data storage are documented (GitHub API, encrypted credentials)
- [ ] FAQ matches current UX (one-click GitHub setup, not wp-config-only)
- [ ] Screenshots section matches files you will upload to SVN `assets/` (optional for approval, recommended for listing)

## Translations (i18n)

- [ ] `languages/webba-deploy.pot` included in release zip (~198 strings)
- [ ] Regenerate after UI changes: `./scripts/make-pot.sh` or `composer make-pot`
- [ ] Text domain `webba-deploy` on all user-facing strings
- [ ] After wordpress.org approval: translations via [translate.wordpress.org](https://translate.wordpress.org/projects/wp-plugins/webba-deploy/)

Local `.mo` files (optional): compile `it_IT.po` → `languages/webba-deploy-it_IT.mo` with Poedit or `msgfmt`.


Build with the release script (recommended):

```bash
./build-release.sh --all
```

Outputs:

| File | Purpose |
|------|---------|
| `build/webba-deploy-{version}.zip` | Submit to wordpress.org for review |
| `build/webba-deploy-wordpress-org-assets-{version}.zip` | Upload to SVN `assets/` after approval |

Regenerate directory PNGs only: `./build-release.sh --assets`

Manual alternative:

```bash
rsync -a --exclude-from=.distignore --exclude build/ --exclude scripts/ --exclude assets/wordpress-org/ ./ /tmp/webba-deploy/
cd /tmp && zip -r webba-deploy.zip webba-deploy/
```

Verify the zip:

- [ ] No `vendor/`, `.git/`, `composer.json`, `PLAN.md`, or `webba-deploy-config.php`
- [ ] Contains `LICENSE`, `readme.txt`, `uninstall.php`, `webba-deploy.php`, `includes/`, `assets/`, `languages/webba-deploy.pot`
- [ ] Plugin folder name inside zip is `webba-deploy/` (not nested twice)

## Code quality

- [ ] `composer install && composer run phpcs` passes (or fix reported issues)
- [ ] PHP syntax check on all plugin PHP files
- [ ] CI green on `main`

## Functional testing (clean WordPress install)

- [ ] Activate plugin — no PHP notices/warnings
- [ ] Add public plugin from GitHub URL — deploy succeeds
- [ ] **Webba Deploy → GitHub → Set up with GitHub** — manifest flow on HTTPS site
- [ ] Continue installation on GitHub — select repos — return shows connected
- [ ] Add private package — repo appears in picker — deploy succeeds
- [ ] **Plugins** screen shows update when remote branch moves — update works
- [ ] Push-to-deploy REST URL with valid secret triggers deploy
- [ ] Push-to-deploy with wrong secret returns 401/403
- [ ] Uninstall **without** opt-in — package options remain (expected)
- [ ] Uninstall **with** opt-in enabled — options removed

## Security (reviewers will ask)

- [ ] All admin actions use `manage_options` (or tighter where appropriate) and nonces
- [ ] Outbound HTTP limited to GitHub hosts (`ApiClient`, `ArchiveDownloader`)
- [ ] GitHub App private key never logged or exposed in HTML
- [ ] REST deploy endpoint uses secret + rate limiting
- [ ] Prepared notes for reviewer: manifest flow, `SecretEncryption`, optional wp-config override

## WordPress.org assets (after approval — SVN `assets/`)

These are **not** in the plugin zip; they power the plugin directory page. Generated by `scripts/generate-wordpress-org-assets.py` (run via `./build-release.sh --assets`):

- [ ] `assets/wordpress-org/icon-256x256.png` — plugin directory icon
- [ ] `assets/wordpress-org/icon-128x128.png`
- [ ] `assets/wordpress-org/banner-772x250.png`
- [ ] `assets/wordpress-org/banner-1544x500.png`

After SVN access: upload the four PNGs to `plugins.svn.wordpress.org/webba-deploy/assets/` (or use the assets zip from `./build-release.sh --all`).

**Admin menu icon:** the backend uses WordPress core `dashicons-download` (see `includes/Admin/Menu.php`). That is separate from directory icons above.

## SVN layout (after approval)

```
plugins.svn.wordpress.org/webba-deploy/
├── trunk/              ← ongoing development
├── tags/1.0.0/         ← release users download (must match Stable tag)
└── assets/             ← banners/icons for wordpress.org listing
```

- [ ] Commit release to `tags/X.Y.Z/`
- [ ] Update `trunk/` to same or next dev version
- [ ] Optional: GitHub Action to deploy tags to SVN (e.g. 10up/action-wordpress-plugin-deploy)

## Submission form

- [ ] Short note to reviewers explaining GitHub App credential storage and external API use
- [ ] GPL-compatible — `LICENSE` included, no bundled proprietary code
